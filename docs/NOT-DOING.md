# What this project does not do

Everything this project leaves out on purpose, in one place, with the reason
and the cost of leaving it out. A reviewer who asks "why not X?" should find X
here.

This page defines nothing. Each row summarizes a decision or a limit whose
authoritative text is in the section it links to, as
[the documentation map](README.md#one-definition-per-fact) requires; where the
two differ, the linked section is right.

## Decided by the owner

| Not done                                      | Why                                                                                                                                     | What it costs                                                                                                                                       | Defined in                                                                                                           |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| A store-side (Lua) admission script           | It would put the decision in a second language that the mock library cannot run, so the required mocked tests would no longer reach it  | Two transactions per request; a rejected entry counts against concurrent requests until it is removed, or for the rest of the hour if removal fails | [Concurrent safety](specs/rate-limiting.md#concurrent-safety), [rate limiting Limits](specs/rate-limiting.md#limits) |
| A rolling window                              | The brief asks for a count that resets every hour, with a reset time; a fixed UTC hour gives both                                       | Up to twice the cap across an hour boundary; hosts need synchronized clocks                                                                         | [Fixed hour](specs/rate-limiting.md#fixed-hour)                                                                      |
| Continuous integration                        | Judged unneeded for this submission; checks are run by hand and recorded with the revision they ran on                                  | Nothing runs on a pull request; each "passes" rests on a recorded run                                                                               | [Platform Limits](specs/platform.md#limits), [verification record](VERIFICATION.md)                                  |
| Refusing the demo tokens outside development  | `docker compose up` alone must give a working demo                                                                                      | A deployment that keeps them is open to anyone who reads this repository; only the loopback bindings keep the demo local                            | [Platform Limits](specs/platform.md#limits)                                                                          |
| A second store, such as a relational database | Redis already holds the quota, and the user registry fits beside it                                                                     | One more Redis read per authenticated request; a Redis outage also fails authentication                                                             | [Users are registered in Redis](specs/platform.md#users-are-registered-in-redis-not-configured)                      |
| Automatic retry of admin actions              | A failed or lost reply does not prove nothing was written: a repeated reset could erase newer usage, a repeated grant could grant twice | After an unclear failure the admin reads the current state and decides                                                                              | [Admin API rule 7](specs/admin-api.md#behavior), [P17](PITFALLS.md#p17-retrying-an-admin-action-automatically)       |
| MUI, Ant Design, shadcn/ui or Chakra          | Mantine covers forms, alerts and notifications in one family; the comparison was from general knowledge, not a trial                    | Every screen is written against Mantine; replacing it rewrites the views                                                                            | [UI library: Mantine](specs/dashboard.md#ui-library-mantine)                                                         |

## Production concerns left out

The brief asks for a production-minded solution; these parts of a production
system were not built, and nothing in this repository claims them.

| Not done                                                                                       | Why                                                                                                                                 | What it costs                                                            | Defined in                                                                                                                          |
| ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| Production authentication: an identity provider, expiry, revocation, per-person admin identity | The brief names no way to know the caller; a guard maps a registered token to the ID, and a provider would replace only that lookup | Static public demo tokens; one shared admin token                        | [Identity comes from a credential](specs/platform.md#identity-comes-from-a-credential), [Platform Limits](specs/platform.md#limits) |
| TLS, and a password on the Compose Redis                                                       | The demo is bound to loopback                                                                                                       | Off loopback, tokens would travel in clear text                          | [Platform Limits](specs/platform.md#limits)                                                                                         |
| Redis replication, failover or Cluster                                                         | One Redis holds all shared state                                                                                                    | Redis is a single point of failure                                       | [Platform Limits](specs/platform.md#limits)                                                                                         |
| Failing open, or a per-process fallback counter, when Redis is down                            | A limiter that cannot count must not pretend to; a counter per process splits the quota                                             | While Redis is unreachable, limited routes answer 503                    | [Rate limiting rule 9](specs/rate-limiting.md#behavior)                                                                             |
| A load balancer with session affinity                                                          | The demo runs one API process; a second one serves only the two-process check                                                       | A client that polls through a balancer to two processes is not supported | [Live updates Limits](specs/live-updates.md#limits)                                                                                 |
| A load test                                                                                    | No claim is made without a measurement behind it                                                                                    | No throughput or latency figure exists; only bounded runs on one machine | [Not verified](VERIFICATION.md#not-verified)                                                                                        |
| Removing users or changing their tokens                                                        | Not asked for                                                                                                                       | A registered user stays until Redis loses its data                       | [Platform Limits](specs/platform.md#limits)                                                                                         |

## Scale left out

| Not done                                         | Why                                                                                                                | What it costs                                                             | Defined in                                                                                         |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Rooms or per-user subscriptions for events       | Each dashboard would subscribe again on every page, filter or selection change; every dashboard is an admin anyway | Delivery grows with all users' requests times open dashboards, unmeasured | [Every dashboard receives every event](specs/live-updates.md#every-dashboard-receives-every-event) |
| Indexes or kept totals for filters and analytics | Status changes with every request and every hour, so an index would burden admission and need hourly repair        | Filtered pages and analytics take time that grows with the population     | [Numbered pages](specs/admin-api.md#numbered-pages-filtered-by-reading-in-batches)                 |

## Delivery guarantees left out

| Not done                                 | Why                                                                            | What it costs                                                                               | Defined in                                                                                                                                 |
| ---------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| A durable event log, an outbox or replay | Snapshot reads repair the current state, so a missed event is not needed again | An event lost while Redis is down is never replayed; its change waits for the next snapshot | [Live updates rule 6](specs/live-updates.md#behavior), [Window, then version](specs/live-updates.md#window-then-version-snapshots-repair)  |
| An event for every rejected request      | A blocked client retries at once, so an event per 429 multiplies work          | A blocked user's Last Request and history change at the next snapshot, not live             | [One alert per window](specs/live-updates.md#one-alert-per-window-re-armed-by-a-generation), [Dashboard Limits](specs/dashboard.md#limits) |
| A read triggered by an event             | Events would cause reads, and reads under steady traffic would never catch up  | A filtered page's members change at the next refresh                                        | [Window, then version](specs/live-updates.md#window-then-version-snapshots-repair)                                                         |
| Exactly-once alerts                      | The dashboard keeps no record of alerts shown                                  | An event delivered twice alerts twice                                                       | [Live updates Limits](specs/live-updates.md#limits)                                                                                        |

## Libraries and services not added

| Not added                                        | Why                                                                             | What it costs                                                          | Defined in                                                                                        |
| ------------------------------------------------ | ------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Nest's throttler or `rate-limiter-flexible`      | Neither has reset, grant or suspension; the second charges rejected attempts    | The window, its keys and their tests are code to maintain              | [Written here](specs/rate-limiting.md#written-here-not-taken-from-a-limiter-library)              |
| A query or state library                         | It would not order events against snapshot reads                                | Queueing and ordering snapshot reads are code to maintain              | [Live state in one hook](specs/dashboard.md#live-state-in-one-hook-no-state-library)              |
| A schema library                                 | A dependency and a second definition of every payload                           | A field a guard omits goes unnoticed                                   | [Shape checks written by hand](specs/dashboard.md#shape-checks-written-by-hand)                   |
| A mock server                                    | Fixtures behind a development-only import let screens be reviewed without Redis | Fixtures can drift; `npm run check:contracts` guards them              | [Fixture mode](specs/dashboard.md#fixture-mode)                                                   |
| `@nestjs/config`                                 | A dependency for four variables                                                 | A change needs a restart                                               | [Configuration is checked once](specs/platform.md#configuration-is-checked-once-before-listening) |
| Nest's monorepo mode                             | Built around its CLI, for a dashboard that is not Nest                          | A toolchain that cannot read TypeScript source would need a build step | [One types-only package](specs/platform.md#one-types-only-package-carries-the-shared-contract)    |
| A static host, a proxy or CORS for the dashboard | One more service, or a wider door for other origins                             | A changed page needs a new image                                       | [The API serves the dashboard](specs/platform.md#the-api-serves-the-dashboard)                    |

## Checks not done

The browser behavior is checked by tests in jsdom and one recorded pass by hand
in Chromium; there is no browser test suite. What was not checked at all,
including other browsers, a hidden tab in a real browser, sustained load, more
than one host, TLS and a Redis failover, is listed under
[Not verified](VERIFICATION.md#not-verified), and what the pitfall checks
cannot notice under [Pitfalls](VERIFICATION.md#pitfalls).
